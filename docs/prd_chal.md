# PRD: 구구단 챌린지

상태: 수정 후 명세 검토 대기
작성일: 2026-08-28

## 가정

1. 이 기능은 로그인한 학생이 사용하는 현재 웹 앱(React/Vite + Express)에 추가한다.
2. 챌린지는 1단부터 9단까지의 곱셈을 대상으로 하며, 현재의 일반 연습(2단부터 9단)은 바꾸지 않는다.
3. 홈에서 선택하는 챌린지 방식은 `답 말하기`, `답 누르기`, `식 말하기`, `식 누르기` 네 가지다. 한 번 선택하면 해당 시도와 오답 재도전이 끝날 때까지 바꾸지 않는다.
4. `도전하기`를 누르면 문제 수 설정 화면으로 이동한다. 문제 수는 20, 25, 30개 중 선택하며 기본값은 25개다.
5. 결과의 별은 정확도 기준으로만 계산한다. 풀이 시간은 결과와 동점 순위를 위한 보조 기준으로 사용한다.
6. 오답 재도전은 결과를 본 직후, 이번 시도에서 틀린 문제만 같은 챌린지 방식으로 다시 푸는 기능이다. 재도전 문제 수에는 20~30개 제한을 적용하지 않는다.
7. 챌린지 랭킹은 문제 수(20개/25개/30개)별로 완전히 분리한다. 공정한 비교를 위해 같은 문제 수 안에서도 네 가지 챌린지 방식별로 따로 순위를 매긴다.
8. 음성 평가는 기존 Gemini 기반 일괄 녹음·채점 흐름을 확장한다. 20~30문항을 답하는 데 필요한 녹음 시간 상향은 구현 단계에서 성능과 비용을 확인한다.

## 목표

9단까지 익힌 학생이 단별 순서를 외운 정도를 넘어, 1~9단이 섞인 문제를 빠르고 정확하게 풀도록 돕는다.

학생은 홈 화면에서 네 가지 챌린지 방식 중 하나를 고르고 `도전하기`를 누른다. 다음 화면에서 문제 수를 정한 뒤 챌린지를 시작한다. 완료 화면에서는 정답 수, 시간, 별 등급, 문항별 정오답과 같은 문제 수·방식의 랭킹을 확인하며, 틀린 문항만 재도전할 수 있다.

## 범위와 모듈

| 모듈 ID | 책임 | 의존성 |
| --- | --- | --- |
| `challenge-session` | 홈 진입, 네 방식 선택, 문제 수 설정, 1~9단 혼합 문제 생성, 방식 고정, 진행 상태 | 없음 |
| `challenge-evaluation` | 말하기/누르기와 답/식 유형의 결과를 공통 형식으로 정규화하고 별을 계산 | `challenge-session` |
| `challenge-ranking` | 문제 수와 챌린지 방식별로 챌린지 기록을 저장·조회·정렬 | `challenge-evaluation` |
| `challenge-retry` | 오답 목록을 만들고 같은 방식으로 재도전을 시작 | `challenge-evaluation` |

구현 순서: `challenge-session` → `challenge-evaluation` → `challenge-ranking`, `challenge-retry`

## 홈 화면과 사용자 흐름

### 홈 화면 (데스크톱)

홈 화면은 2열 구조로 구성한다.

```text
┌──────────────────────────┬──────────────────────────┐
│ 말하기 구구단             │ 구구단 챌린지             │
│ (기존 일반 연습)          │ [답 말하기] [답 누르기]   │
├──────────────────────────┤ [식 말하기] [식 누르기]   │
│ 누르는 구구단             │                            │
│ (기존 일반 연습)          │       [도전하기]           │
└──────────────────────────┴──────────────────────────┘
```

- 왼쪽 절반에는 기존 `말하기 구구단`과 `누르는 구구단` 카드를 세로로 배치한다.
- 오른쪽 절반에는 두 기존 카드 높이에 맞춘 `구구단 챌린지` 카드를 배치한다.
- 좁은 화면에서는 세 카드를 한 열로 쌓되, 챌린지 카드의 버튼 순서와 동작은 유지한다.
- 챌린지 카드에서 네 버튼 중 하나만 활성화할 수 있다. `도전하기`는 선택한 방식을 가지고 문제 수 설정 화면으로 이동한다.

### 챌린지 흐름

1. 학생은 챌린지 카드에서 네 가지 방식 중 하나를 선택한다.
2. `도전하기`를 누르면 문제 수 설정 화면이 열린다.
3. 학생은 20개, 25개, 30개 중 하나를 선택하고 `챌린지 시작`을 누른다.
4. 앱은 1×1부터 9×9까지의 81개 식에서 선택한 수만큼 중복 없는 식을 무작위로 출제한다.
5. 진행 화면에는 선택한 방식에 맞는 입력 UI만 보인다. 방식 전환 UI, 자동 전환, 전환 안내는 제공하지 않는다.
6. 완료 후 결과 화면에서 정답 수, 전체 문제 수, 경과 시간, 별 등급, 문항별 정오답을 표시하고 해당 문제 수·방식의 랭킹에 기록한다.
7. 오답이 하나 이상이면 `틀린 문제 다시 풀기`를 표시한다. 이 버튼은 해당 오답만으로 새 시도를 시작하며, 원래 선택한 챌린지 방식을 유지한다.

## 기능 요구사항

### FR-1. 챌린지 방식 선택과 고정

- 홈의 챌린지 카드에는 아래 네 개의 버튼과 `도전하기` 버튼이 있다.

| 버튼 | 문제 화면 | 학생의 입력 |
| --- | --- | --- |
| `답 말하기` | `3 x 4 = ?` | `12`를 말한다. |
| `답 누르기` | `3 x 4 = ?` | 정답 숫자 `12`를 누른다. |
| `식 말하기` | `12 = ?` | `3 x 4`를 말한다. |
| `식 누르기` | `12 = ?` | 식 `3 x 4`를 누른다. |

- `도전하기`는 방식이 선택되기 전에는 비활성화한다.
- 선택한 방식은 문제 수 설정 화면, 진행 화면, 결과 화면, 오답 재도전에서 읽기 전용으로 보관한다.
- 진행 중 또는 재도전 중에 다른 방식으로 바꾸는 버튼이나 자동 대체 동작은 없다.

### FR-2. 문제 수 설정과 시작

- `도전하기` 다음 화면에는 `20개`, `25개`, `30개` 선택 버튼과 `챌린지 시작` 버튼이 있다.
- 기본 선택은 25개이며, 한 문제 수만 선택할 수 있다.
- `챌린지 시작`은 선택한 방식과 문제 수를 포함한 새 시도를 만들고 진행 화면으로 이동한다.

### FR-3. 혼합 문제 생성과 진행

- 문제 풀은 `1 x 1`부터 `9 x 9`까지다.
- 본 챌린지 한 번에는 동일한 식이 두 번 출제되지 않는다.
- 출제 순서는 매 시도마다 무작위다.
- 진행 화면은 현재 문항 번호와 전체 문항 수를 보여 준다.
- `답` 방식은 식을 보여 주고 답을 받으며, `식` 방식은 곱을 보여 주고 식을 받는다.
- `누르기` 방식은 한 문항씩 보기 중 하나를 눌러 진행한다. `말하기` 방식은 출제 순서 전체에 대한 녹음을 제출해 채점한다.

### FR-4. 입력 방식 고정과 실패 처리

- 말하기 방식에는 녹음·제출 UI만, 누르기 방식에는 선택지 버튼 UI만 제공한다.
- 말하기에서 마이크 권한 또는 채점에 실패하면 같은 말하기 시도를 재시도할 수 있게 안내한다. 누르기 방식으로 바꾸라는 안내는 하지 않는다.
- 상태 전이에서도 방식을 검증하여, URL 이동이나 브라우저 뒤로 가기로 다른 방식 화면에 진입해도 현재 시도의 방식과 일치하지 않으면 진행할 수 없게 한다.

### FR-5. 채점과 별 등급

- 결과는 방식과 무관하게 문항, 정답, 학생 답, 정오답을 포함한 공통 형식으로 만든다.
- 별은 아래 표의 정확도 경계값으로 계산한다. 100%는 반드시 5개 별이다.

| 정확도 | 별 | 등급명 |
| --- | --- | --- |
| 100% | 5 | 구구단 마스터 |
| 90~99% | 4 | 챌린지 달인 |
| 80~89% | 3 | 실력 쑥쑥 |
| 70~79% | 2 | 조금만 더 |
| 0~69% | 1 | 다시 도전 |

- 결과 화면은 `정답 수 / 전체 문제 수`, 경과 시간, 별과 등급명, 문항별 결과를 보여 준다.

### FR-6. 문제 수·방식별 챌린지 랭킹

- 챌린지 기록에는 문제 수(20/25/30), 챌린지 방식(네 가지), 정답 수, 별, 풀이 시간을 저장한다.
- 랭킹의 비교 그룹은 `문제 수 + 챌린지 방식`이다. 따라서 20개·답 말하기와 25개·답 말하기, 20개·답 말하기와 20개·답 누르기는 서로 다른 랭킹이다.
- 각 랭킹은 정답 수가 높은 순, 동점이면 풀이 시간이 짧은 순으로 정렬한다.
- 결과 화면과 랭킹 화면은 현재 문제 수와 방식을 명확히 표시하고, 다른 문제 수의 기록을 섞어 보여 주지 않는다.
- 일반 연습 명예의 전당 기록과 챌린지 랭킹은 서로 섞지 않는다.

### FR-7. 오답 재도전

- 오답이 있을 때에만 재도전 버튼을 표시한다.
- 재도전은 오답 문항만, 원래 챌린지와 같은 방식으로 시작한다.
- 재도전 문항은 원래 문항의 오답 목록을 무작위로 섞되, 같은 식을 추가하거나 새 문제를 섞지 않는다.
- 재도전 결과도 별과 문항별 결과를 보여 주고, 다시 틀린 문항이 있으면 재도전을 반복할 수 있다.
- 오답 재도전은 학습용 보조 시도이므로 챌린지 랭킹에는 저장하지 않는다.

## 비기능 요구사항

- 문제 생성은 순수 함수로 만들고, 테스트에서 난수 주입으로 출제 순서와 중복 여부를 재현할 수 있어야 한다.
- 키보드만으로 챌린지 방식·문제 수·누르기 답을 선택할 수 있어야 하며, 선택 상태에는 접근 가능한 이름과 `aria-pressed`를 제공한다.
- 음성 녹음/채점 실패는 학생에게 이해하기 쉬운 메시지로 표시하고, 실패한 답안을 정답이나 랭킹 기록으로 저장하지 않는다.
- 클라이언트가 보낸 문제 목록·정답 수를 그대로 신뢰하지 않는다. 서버는 말하기 챌린지의 문제 수, 문항 범위, 중복 여부, 곱셈식 형식을 검증한다.

## 데이터 및 API 영향

```ts
type ChallengeMode = 'answer-speech' | 'answer-tap' | 'expression-speech' | 'expression-tap';
type ChallengeQuestion = { expression: string; answer: string };

type ChallengeAttempt = {
  questionCount: 20 | 25 | 30;
  mode: ChallengeMode;
  questions: ChallengeQuestion[];
  retryDepth: number;
};
```

- `challenge_records` 테이블(또는 동일한 책임의 명확한 별도 저장 모델)을 추가한다. 최소 필드는 `student_id`, `school_id`, `question_count`, `challenge_mode`, `total_correct`, `total_time_ms`, `star_count`, `created_at`이다.
- 랭킹 쿼리는 `school_id`, `question_count`, `challenge_mode`을 반드시 조건으로 사용한다. 학생별 최고 기록만 보여 줄지, 모든 시도를 보여 줄지는 로드맵 단계에서 결정한다.
- 결과 화면에서 재도전에 필요한 오답 문항은 클라이언트 상태에만 유지한다.
- 말하기 평가 요청은 일반 연습의 `table`/`mode` 검증과 분리된 챌린지 계약을 가진다. 예: `practiceKind: 'challenge'`, `challengeMode`, `expectedQuestions`, `totalTime`.
- 답 말하기는 숫자 답을, 식 말하기는 `n x n` 형식의 식을 유연하게 판정하되 서버가 채점 결과와 기대 답의 일치 여부를 검증한다.

## 코드 스타일

- 클라이언트는 TypeScript ES 모듈, 서버는 CommonJS를 유지한다.
- 문제 생성과 별 계산은 UI에서 분리한 순수 함수로 작성한다.
- 상태 이름은 기존 Zustand 관례를 따라 명확한 동사형 setter를 쓴다.

```ts
export function calculateChallengeStars(correct: number, total: number): 1 | 2 | 3 | 4 | 5 {
  const accuracy = total === 0 ? 0 : correct / total;
  if (accuracy === 1) return 5;
  if (accuracy >= 0.9) return 4;
  if (accuracy >= 0.8) return 3;
  if (accuracy >= 0.7) return 2;
  return 1;
}
```

## 테스트 전략

- 단위: 81개 문제 풀에서의 범위, 요청 문제 수, 중복 없음, 답/식 문제 변환, 재도전 오답 보존, 별 경계값(100/90/80/70%)을 테스트한다.
- 컴포넌트: 2열 홈 배치, 네 버튼 단일 선택, `도전하기` 전제조건, 문제 수 설정, 방식 잠금, 답/식·말하기/누르기 진행, 결과와 오답 재도전을 React Testing Library로 테스트한다.
- 서버: 말하기 챌린지에서 20/25/30개 유효 문항은 허용하고, 범위 밖 수·중복 식·잘못된 문항 수·잘못된 방식·일반 연습 계약 혼합은 거부하는지 테스트한다.
- 랭킹: 문제 수와 방식이 다른 기록이 같은 랭킹에 섞이지 않으며, 정답 수 내림차순·시간 오름차순으로 정렬하는지 테스트한다.
- 회귀: 기존 말하기·누르기 일반 연습의 테스트와 프로덕션 빌드를 모두 통과시킨다.

## 경계

- 항상: 입력 방식 고정을 UI와 상태 전이 모두에서 강제하고, 서버에서 음성 챌린지 문항을 검증하고, 문제 수·방식별로 랭킹을 분리하고, 구현 후 클라이언트/서버 테스트와 빌드를 실행한다.
- 먼저 확인: 실제 DB 마이그레이션 적용, 새 외부 의존성 추가, Gemini 모델/비용 정책 변경.
- 금지: 학생이 진행 중 입력 방식을 바꾸게 하기, 클라이언트 점수만으로 음성 결과를 신뢰하기, 서로 다른 문제 수의 랭킹을 섞기, 일반 연습 기록이나 기존 테스트를 제거하기.

## 성공 기준

1. 데스크톱 홈은 왼쪽 절반의 `말하기 구구단`·`누르는 구구단`과 오른쪽 절반의 `구구단 챌린지` 카드로 보이며, 모바일에서는 접근 가능한 한 열 배치로 바뀐다.
2. 챌린지 카드에 `답 말하기`, `답 누르기`, `식 말하기`, `식 누르기`, `도전하기`가 있고, 한 방식 선택 전에는 도전할 수 없다.
3. 다음 화면에서 20/25/30문제 중 하나를 설정하고 `챌린지 시작`을 할 수 있다.
4. 한 챌린지의 모든 식은 1~9 범위이고 식이 중복되지 않으며, 현재 문제 수가 정확히 표시된다.
5. 선택한 방식은 시작부터 결과 및 오답 재도전까지 바뀌지 않는다.
6. 완료 시 정확도 경계에 맞는 별/등급, 정답 수, 시간, 문항별 결과가 표시된다.
7. 챌린지 랭킹은 문제 수와 방식 조합별로 분리되어 정답 수 우선·시간 차순으로 표시된다.
8. 오답이 있을 때만 같은 방식의 오답 재도전을 할 수 있고, 재도전에는 원래 오답 이외의 문항이 들어가지 않으며 랭킹에는 반영되지 않는다.
9. 기존 일반 연습 흐름과 모든 기존 테스트가 계속 동작한다.

## 검토가 필요한 사항

1. 랭킹은 현재 문제 수와 네 챌린지 방식을 모두 분리합니다. 같은 문제 수의 네 방식을 한 랭킹으로 합치는 편을 원하시면 이 규칙을 바꾸겠습니다.
2. 말하기 챌린지의 녹음 제한은 60초에서 몇 초로 정할까요? 계획 단계에서는 120초를 기본 후보로 검증하겠습니다.
3. 81개 식 중 `2 x 3`과 `3 x 2`는 서로 다른 문제로 취급합니다. 이 정책이 맞나요?
