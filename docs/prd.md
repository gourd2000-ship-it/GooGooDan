# GooGooDan 학생 계정·학습 현황 관리 PRD

상태: 설계 결정 반영 완료 — 구현 전 계획 승인 필요
작성일: 2026-08-24

확정 결정:

- 관리자는 **Google Workspace 계정**으로 로그인한다.
- 학생 로그인 화면에는 학교 선택을 두지 않고, **학교별 전용 접속 주소**가 학교를 식별한다.

## 1. 목표

GooGooDan을 익명 일회성 학습 앱에서 **교사가 배정한 학생 계정으로 접속하고, 같은 학생의 학습 기록을 누적·관리하는 서비스**로 확장한다.

학생은 브라우저를 새로고침하거나 여러 탭을 열어도 로그인 상태를 유지한다. 명예의 전당에는 동일 학생이 여러 줄로 반복되지 않고, 조건별 최고 기록만 한 번 표시된다. 교사는 학교·학년·반별 학생의 2~9단 성취를 한 화면에서 보고 학생 정보를 관리한다.

## 2. 기능 묶음과 의존성

이 요구는 독립적으로 검증 가능한 다섯 기능으로 나뉜다.

| 모듈 ID | 책임 | 의존성 |
| --- | --- | --- |
| `tenant-structure` | 학교별 전용 주소와 학교 데이터 경계 | 없음 |
| `admin-access` | Google Workspace 기반 관리자 접근 제어 | `tenant-structure` |
| `student-identity` | 학생 계정, 4자리 접속번호, 세션, 프로필 | `tenant-structure` |
| `record-ownership` | 기록의 학생 귀속, 최고 기록 랭킹 | `student-identity` |
| `roster-management` | 학생 단건 등록, 일괄 배정·수정 | `admin-access`, `student-identity` |
| `progress-dashboard` | 성취 매트릭스와 필터 | `admin-access`, `student-identity`, `record-ownership` |

구현 순서는 **구조 → 공통 기능 → 개별 기능**으로 고정한다.

1. 구조: `tenant-structure`, `admin-access`, 데이터 스키마
2. 공통 기능: `student-identity`, `record-ownership`, 권한·세션·공용 API
3. 개별 기능: 학생 로그인/프로필, `roster-management`, `progress-dashboard`

## 3. 사용자 흐름

### 학생

1. 학생은 학교별 전용 접속 주소로 들어온 뒤 학년 드롭다운, 반 드롭다운, 4자리 접속번호로 접속한다. 학교명과 이름은 로그인 화면에 입력하지 않는다.
2. 접속번호는 휴대폰 형태의 3×4 키패드로 입력한다. 누른 숫자는 보이지 않고 네 개의 점으로 입력 진행만 표시한다.
3. 네 번째 숫자를 누르면 자동으로 로그인 요청한다. 실패하면 입력 점을 비우고 안내를 표시한다.
4. 성공하면 서버 세션을 복원할 수 있으므로 새로고침·뒤로 가기·같은 브라우저의 추가 탭에서도 이름 입력 화면으로 돌아가지 않는다.
5. 학생은 개인정보 화면에서 현재 번호를 확인 절차로 사용해 새 4자리 번호로 바꾸고, 로그아웃할 수 있다. 학교·학년·반·이름은 읽기 전용이다.
6. 말하기/누르기 구구단을 완료할 때마다 기록은 같은 학생 ID에 누적된다.

### 관리자

1. 관리자는 Google Workspace 계정으로 로그인한 보호된 관리 화면에서 학교, 학년, 반, 이름을 가진 학생을 단건 등록할 수 있다.
2. 관리자는 CSV 일괄 등록으로 여러 학생에게 4자리 접속번호를 배정한다. 시스템은 같은 학교·학년·반 안에서 중복되지 않는 번호만 허용한다.
3. 관리자는 이름과 불변 고유 ID를 제외한 학교, 학년, 반, 접속번호를 수정할 수 있다.
4. 대시보드는 기본적으로 전체 학생을 표시하고, 학교·학년·반 필터로 좁힐 수 있다.

## 4. 상세 요구사항

### 4.1 학생 로그인과 세션

- 학년과 반 목록은 활성 학생 계정이 있는 값만 선택지로 제공한다. 지원 범위는 초등 1~6학년이며 반은 양의 정수다.
- 키패드는 `1–9`, `지우기`, `0`, `전체 지우기`의 12개 버튼으로 구성한다. 마우스·터치와 키보드 모두 조작할 수 있어야 한다.
- 비밀번호 점은 0~4개만 표시하며 실제 숫자, URL, 브라우저 로그에 접속번호를 남기지 않는다.
- 전용 접속 주소의 호스트명으로 학교를 확정한다. 서버는 호스트명과 일치하는 학교의 학생만 로그인 후보로 조회한다.
- 로그인 성공 시 서버가 만료일을 가진 보안 세션 쿠키를 설정한다. 앱 시작 시 `GET /api/auth/session`으로 세션을 복원한다.
- 로그아웃은 서버 세션을 폐기하고 클라이언트의 사용자·학습 상태를 초기화한다.
- 세션 만료 또는 인증 실패 시에만 로그인 화면으로 이동한다. 브라우저 뒤로 가기로 로그인 화면을 다시 표시하지 않도록 화면 이력을 교체한다.

### 4.2 기록 귀속과 명예의 전당

- `POST /api/evaluate`와 `POST /api/record`는 이름 대신 인증된 세션의 학생 ID에 기록을 귀속한다. 클라이언트가 보내는 `userName`은 신뢰하지 않는다.
- 원본 기록은 분석과 재도전을 위해 보존한다. 기록에는 학생 ID, 단, 순서, 학습 유형, 게임 모드, 정답 수, 점수, 소요 시간을 저장한다.
- 명예의 전당은 선택한 학습 유형과 단 필터 안에서 **학생당 한 행**만 보인다. 동점이면 더 짧은 시간이 높은 기록이다.
- 전체 단 필터에서도 학생당 최고 기록 한 행만 표시한다. 단별 필터에서는 해당 단의 최고 기록을 표시한다.
- DB를 사용할 수 없을 때 기록 저장은 성공으로 보이면 안 된다. 학생에게 재시도 상태를 보이고 명예의 전당에는 샘플 데이터를 섞어 표시하지 않는다.

### 4.3 성취 대시보드

- 행은 학생, 열은 2단부터 9단까지다. 각 셀에는 말하기 최고 점수와 누르기 최고 점수를 함께 표시하고 그중 큰 값을 강조한다.
- 셀 배경색은 두 방식 중 높은 점수에 따라 정한다.

| 최고 점수 | 색 | 의미 |
| --- | --- | --- |
| 100점 이상 | 초록 | 기준 점수 도달 |
| 30점 이상 100점 미만 | 노랑 | 진행 중 |
| 30점 미만 또는 기록 없음 | 빨강 | 재학습 필요 |

- `정답 수 = 10`인 기록이 하나라도 있으면 해당 단에 “모두 정답” 표지를 보인다. 점수와 완전 정답은 별도 개념이다.
- 기본 정렬은 학교, 학년, 반, 이름 오름차순이다. 필터를 적용해도 이 순서를 유지한다.
- 대시보드는 필터 결과의 학생 수와 단별 “모두 정답” 학생 수를 함께 보여 준다.

### 4.4 학생 정보 관리

- 관리자만 목록 조회·등록·일괄 등록·수정 API를 사용할 수 있다.
- 수정 가능: 학교, 학년, 반, 접속번호. 수정 불가: 학생 ID, 이름.
- 접속번호는 평문으로 저장하거나 응답에 반환하지 않는다. 관리자 화면은 재설정 성공 여부와 마지막 변경 시각만 표시한다.
- CSV는 `school,grade,class,name,accessCode` 열을 사용한다. 접속번호를 빈 칸으로 두면 서버가 4자리 번호를 생성한다. 오류 행은 행 번호와 사유를 반환하고, 유효 행만 저장하지 않는다(전체 원자성).

## 5. 데이터·API 계약

### 데이터 모델

| 엔터티 | 주요 필드 | 규칙 |
| --- | --- | --- |
| `students` | `id(UUID)`, `school_name`, `grade`, `class_number`, `student_name`, `access_code_hash`, `is_active` | 학교·학년·반 안에서 활성 접속번호는 유일 |
| `student_sessions` | `id`, `student_id`, `token_hash`, `expires_at`, `revoked_at` | 원문 토큰은 쿠키에만 존재 |
| `records` | 기존 필드 + `student_id`, `total_correct` | 모든 새 기록은 학생 ID를 가져야 함 |
| `admins` | Google Workspace subject, 이메일, 역할, 학교 ID | Google ID 토큰 검증 후 학교별 권한 부여 |

기존 익명 `records`는 삭제하지 않고 `student_id = NULL`로 보존한다. 새 대시보드·랭킹에서는 학생 ID가 있는 기록만 사용한다.

### 새 API

| API | 권한 | 목적 |
| --- | --- | --- |
| `POST /api/auth/student/login` | 공개 | 학년·반·4자리 번호로 로그인 |
| `GET /api/auth/session` | 학생 | 현재 학생과 세션 확인 |
| `POST /api/auth/logout` | 학생 | 현재 세션 폐기 |
| `PATCH /api/auth/access-code` | 학생 | 현재 번호 검증 후 새 번호 설정 |
| `GET /api/admin/students` | 관리자 | 학생 목록·필터 조회 |
| `POST /api/admin/students` | 관리자 | 학생 단건 등록 |
| `POST /api/admin/students/import` | 관리자 | CSV 일괄 등록·번호 배정 |
| `PATCH /api/admin/students/:id` | 관리자 | 허용 필드 수정 |
| `GET /api/admin/progress` | 관리자 | 2~9단 성취 매트릭스 조회 |

기존 `/api/evaluate`, `/api/record`, `/api/ranking`은 인증 및 학생 ID 기준 쿼리로 변경한다.

관리자 인증에는 Google OpenID Connect의 서버측 ID 토큰 검증을 사용한다. 학생과 관리자의 세션·권한은 서로 분리한다.

## 6. 기술 기준

- 클라이언트: React 19, TypeScript, Vite, Zustand, Vitest, React Testing Library
- 서버: Node.js, Express 5, `pg`, Node `crypto`, Node 내장 테스트 러너
- DB: PostgreSQL/Neon
- 세션: `HttpOnly`, `Secure`, `SameSite` 쿠키와 서버측 토큰 해시
- 배포 환경에서 프런트엔드 요청은 `credentials: 'include'`를 사용하고, CORS는 허용 출처를 정확히 지정한다.

## 8. 테스트 전략

- 단위: 접속번호 검증·해시, 세션 만료, 최고 기록 선택, 색상 등급, CSV 행 검증
- API 통합: 학생 로그인/로그아웃, 인증 없는 기록 저장 거부, 학생당 랭킹 한 행, 관리자 권한 거부
- UI: 키패드 점 표시와 자동 제출, 새로고침 세션 복원, 프로필 변경, 필터·성취 셀 색상
- 회귀: 기존 말하기 Gemini 채점과 누르기 채점 모두 동일 학생에게 기록되는지 확인

## 9. 경계

- 항상: 입력 검증, 비밀번호 해시, 인증·권한 테스트, 마이그레이션 롤백 계획, 기존 기록 보존
- 사전 승인 필요: DB 스키마 변경 적용, Google Cloud OAuth 클라이언트 생성·도메인 등록, 신규 CSV 라이브러리 추가, 배포 CORS·쿠키 설정 변경
- 금지: 4자리 번호 평문 저장·로그 기록, 관리자 API 공개, 기존 기록 삭제, 학생 이름으로 소유권 판정

## 10. 성공 기준

1. 학교별 전용 접속 주소에서만 해당 학교 학생이 로그인되며, 학교 선택이나 이름 입력이 필요 없다.
2. 같은 브라우저에서 새로고침·뒤로 가기·추가 탭 이후에도 유효 세션의 학생은 로그인 상태를 유지한다.
3. 학생은 학년·반·키패드 4자리 번호만으로 로그인하며, 입력 숫자가 화면에 노출되지 않는다.
4. 한 학생의 여러 시도는 모두 같은 학생 ID에 기록되고, 명예의 전당은 지정 필터에서 학생당 최고 기록 한 행만 보인다.
5. 관리자는 Google Workspace 계정으로 인증된 뒤에만 필터된 학생별 2~9단의 점수와 학생 관리 기능에 접근한다.
6. 말하기·누르기·랭킹의 기존 테스트와 새 인증·대시보드 테스트가 모두 통과한다.

## 11. 구현 전 결정할 질문

1. **Google Workspace 범위:** 특정 Workspace 도메인만 관리자로 허용할지, 초대된 Google 계정 목록을 허용할지 결정이 필요하다.
2. **접속번호 배정:** 관리자가 직접 4자리를 입력하는지, CSV 빈 칸에 대해 자동 생성하는지, 둘 다 지원하는지 확정이 필요하다.
3. **세션 정책:** 권장 기본값은 14일 유지·로그아웃 시 즉시 폐기다. 학교 정책상 더 짧은 만료 시간이 필요한가?
4. **기존 익명 기록:** 대시보드/랭킹에서 제외하는 것으로 정의했다. 기존 기록을 특정 학생에게 연결해야 하는가?

## 12. 차후 범위

학생 자가 회원가입(학교·학년·반·번호·이름·접속번호 직접 설정)은 이번 릴리스에 포함하지 않는다. 학생 등록 정책과 중복 검증을 별도 명세로 작성한 뒤 구현한다.
