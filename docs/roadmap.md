# 학생 계정·관리 기능 로드맵

확정된 설계 원칙:

- 관리자는 Google Workspace 계정으로 로그인한다.
- 학교는 전용 접속 주소로 구분한다. 학생은 학교를 선택하지 않고 해당 주소에서 학년·반·PIN만 입력한다.

구현은 의도적으로 **구조 → 공통 기능 → 개별 기능** 순서를 지킨다. 각 단계의 공용 계약을 먼저 안정화해, 로그인·명부·대시보드 UI가 서로 다른 방식으로 인증과 데이터를 다루지 않게 한다.

## M0. 구조: 테넌트·인증·데이터 기반

- [ ] 학교별 전용 주소와 `school_id` 해석 규칙을 정의한다.
- [ ] Google Cloud OAuth 클라이언트, 허용 Workspace 정책, 관리자 초기 등록 절차를 설정한다.
- [ ] `schools`, `admins`, `students`, `student_sessions`와 기록 소유권 필드를 추가하는 마이그레이션을 작성한다.
- [ ] 학교 호스트 검증, Google ID 토큰 검증, 관리자 권한 미들웨어, 쿠키/CORS 공통 설정을 구현한다.

완료 기준: 서로 다른 학교의 데이터가 공용 API에서 섞이지 않고, Google 인증을 거친 관리자만 관리자 경로에 접근한다.

## M1. 공통 기능: 학생 세션·기록·집계 계약

- [ ] 학생 PIN 해시·검증, 로그인, 세션 복원·폐기, 접속번호 변경 API를 구현한다.
- [ ] 앱 시작 시 세션을 복원하는 공용 클라이언트 API·Zustand 상태를 구현한다.
- [ ] 말하기/누르기 기록을 인증 학생 ID에 귀속하고, 정답 수를 저장한다.
- [ ] 학생별 최고 기록·동점 시간 규칙을 공용 쿼리/유틸리티로 구현한다.
- [ ] 성취 대시보드에 사용할 학교·학생·단·학습유형별 집계 계약을 구현한다.

완료 기준: UI 없이 API 테스트만으로도 학생 세션, 기록 소유권, 학생당 최고 기록, 학교 경계가 검증된다.

## M2. 개별 기능: 학생 경험

- [ ] 학년·반 드롭다운과 마스킹 3×4 키패드 로그인 화면을 구현한다.
- [ ] 브라우저 새로고침·뒤로 가기·새 탭에서도 세션을 복원하고 로그인 화면 이력을 교체한다.
- [ ] 개인정보 화면에서 접속번호 변경과 로그아웃을 구현한다.
- [ ] 명예의 전당을 학생별 한 행 최고 기록 표시로 변경하고 DB 오류 상태를 표시한다.

완료 기준: 학생은 전용 학교 주소에서 로그인해 두 학습 방식을 완료하고, 같은 학생으로 기록·랭킹을 확인한다.

## M3. 개별 기능: 관리자 명부

- [ ] 학생 단건 등록·목록 조회·허용 필드 수정 API를 구현한다.
- [ ] CSV 형식 검증, 접속번호 자동 생성, 원자적 일괄 등록 API를 구현한다.
- [ ] 관리자 화면에서 학생 검색·등록·수정·일괄 등록을 구현한다.

완료 기준: Google Workspace 관리자는 자신의 학교 학생만 관리할 수 있고, 오류 CSV는 일부 학생만 생성하지 않는다.

## M4. 개별 기능: 성취 대시보드

- [ ] 학교·학년·반 필터와 학생×2~9단 매트릭스를 구현한다.
- [ ] 말하기/누르기 최고 점수와 더 높은 점수 강조를 표시한다.
- [ ] 100점 이상 초록, 30~99점 노랑, 30점 미만·기록 없음 빨강 색상 및 “모두 정답” 표지를 구현한다.

완료 기준: 관리자는 한 화면에서 각 학생의 단별 성취를 정확한 필터·색상·점수로 확인한다.

## M5. 배포 검증과 운영 준비

- [ ] 실제 HTTPS 도메인에서 Google 로그인, `Secure`/`SameSite` 쿠키, CORS credentials를 검증한다.
- [ ] 서버·클라이언트 전체 테스트와 빌드를 실행한다.
- [ ] 학교 주소 배정, 관리자 초기 등록, CSV 템플릿, 장애 대응 절차를 문서화한다.
- [ ] 한 학급 시범 운영으로 PIN 로그인 UX와 대시보드 정확성을 검증한다.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 학교 주소 미등록 또는 잘못된 호스트 | 인증 전에 호스트→학교 해석을 실패 처리하고 관리자만 주소를 등록 |
| Google Workspace 정책 불명확 | 허용 도메인 또는 초대 목록을 M0에서 결정 |
| 4자리 번호 추측 | 해시, 로그인 시도 제한, 세션 만료, 학교·학년·반 범위 제한 |
| 프런트/서버 다른 도메인의 쿠키 차단 | HTTPS 배포 환경에서 credentials/CORS/쿠키 속성을 통합 테스트 |
| 기존 익명 기록 | 보존하되 새 집계에는 `student_id` 기록만 사용 |
